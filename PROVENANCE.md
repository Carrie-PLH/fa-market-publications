# Provenance: Provision Record

This repository is the record behind provisionrecord.com, a Field Assembly market record. It declares its conformance here, as §3.8 of the Field Assembly Record Standard requires.

## Standard version

Collected under the Field Assembly Record Standard **1.2** (§8, market records), effective 2026-09-23, frozen under `versions/1.2/` in the standard's repository and anchored there (entry 2026-09-23T143102Z), recorded in FA-D-20260923-04. Observations captured before the 1.2 effective date (the Lobster Monitor run of 2026-09-22 and the Egg & Butter Brief run of 2026-09-23) are pinned to 1.2 here rather than resolved by §6's date rule, because §8 describes the practice they were collected under and no earlier release does.

## What is met

- Retained release (§8.1): `tools/fetch.py` writes every response body byte for byte under `<title>/captures/<run>/<source>/`, with the response headers (Set-Cookie redacted) and a `capture.json` carrying URL, final URL, retrieval time and SHA-256. Failed fetches are recorded with the error and the source is marked FAILED or PARTIAL; nothing is substituted. A request that carries a credential records the request as written, naming the environment variable rather than its value. Byte-for-byte retention has one sharp edge: a service that rejects a credential may echo it back in the error body, and retaining that body would write the credential into the record. A response containing a secret sent with the request is therefore discarded and the fetch recorded as FAILED. Such a response is an error response, so no reading is lost. This was not hypothetical: the BLS API returned a rejected key in its error message on 2026-09-23, and the capture was removed before it was committed.
- Parsers fail visibly (§8.2): `tools/parse.py` appends rows to `<title>/data/indicators.jsonl`, each naming its capture file and hash; a parser that cannot find its pattern raises and the source is flagged PARSE_FAILED in `data/flags.jsonl`. Rows are never edited.
- The computed set (§8.3): `tools/issue.py` regenerates `numbers.json` from the rows for a named run; every figure in an edition must appear there. One qualification, added 2026-10-18: a source whose report states one period per issue cannot carry its own history, so the comparisons for it exist only because this record keeps every run. Those sources carry `"accumulates": true` in `sources.json` and `issue.py` merges their earlier runs into the computed set, naming them in `numbers.json` under `accumulated_sources`; the named run still wins for every period it reported. Every other source is read from the named run alone, so an issue pinned to an earlier run never silently takes a later revision. `tools/site.py` publishes `numbers.json`, `measures.csv`, `data.csv` and a `dictionary.md` stating each formula and rounding, with calculated rows marked, beside every published edition.
- Like with like, no causal inference, what the record does not do (§8.4, §8.5, §8.8): the methodology page of each title states the rules; the editorial standard in `CLAUDE.md` binds sessions to them.
- Editions immutable and versioned (§8.6): `edition.json` carries status, version, publication and revision dates; the site keeps every edition at its permanent address; corrections are dated on the page and the original text stays visible.
- Original observations by letter (§8.7): Lobster Monitor's consumer reference rows come read-only from the private wedding observation record, sellers appear as letters, and the letter map is on the methodology page.
- Anchoring (§3.6, PROVENANCE §chain): `tools/anchor.py` hashes the captures, data and issues of every title listed in `tools/anchor-paths.txt` into `anchors/`, with RFC 3161 tokens from two authorities. Chain entry 2026-09-22T202107Z covers the Lobster Monitor baseline run. Entry 2026-09-23T153756Z covers 206 files: the September 2026 baselines of the Egg & Butter Brief, Chicken Monitor, Beef Monitor, Pork Monitor and Cheddar Check, and the corrected Lobster Issue 0. Both tokens verify and an OpenTimestamps proof is stored for the second entry.
- Retention (§3.10): captures are never destroyed; a later run supersedes.
- Recipes (§3.11): `<title>/sources.json` is the recipe (URL, fetch method, parser, parser arguments); `config.json` carries fetch settings.

## What is not met, or not yet

- OpenTimestamps: no OTS proof exists for entry 2026-09-22T202107Z (the `ots` client was not installed at anchor time). Later anchor runs are expected to store one; the gap is stated on the edition page.
- Reviewer attribution (§3.9): the edition page carries a reviewer line from `edition.json`; no edition has published yet, so none has been reviewed for publication.
- Verification gate (§3.4): `tools/check.py` reads an issue's prose and its numbers table, pulls out every figure each asserts, and reports any that `numbers.json` does not hold at the precision the prose used. `tools/site.py` checks the built CSVs against `numbers.json`, and the editor reads the issue. What the mechanical check does not establish is that a figure was attached to the right measure: a figure equal to an unrelated stored value passes. A clean run means no figure was invented, not that every figure was used correctly. That weakness is not hypothetical. Until 2026-10-18 `numbers_md_beef` computed the Choice less Select cutout's year-over-year change while formatting the table and `compute_beef` never stored it, so `numbers.md` asserted a figure the computed set did not hold. It passed at the September baseline because the printed value, -6.5%, happened to equal two unrelated stored figures, and it was caught in the 2026-10 issue only because that month's value, 28.5, matched nothing stored. The figure is now computed once and stored; `beef/issues/2026-09-baseline` has not been recomputed and its `numbers.md` still carries the unstored figure. A second limit of the same check was found on 2026-10-18 and is not fixed: in prose the check reads only figures carrying a unit, a percentage, a currency or a scale word, because a bare integer in a sentence is usually a count, a list position or an ordinal. Every number in a table value cell is read. So a plain count asserted in prose, and a quantity written in words, pass unexamined. Both occurred in the draft of Lobster Monitor Issue 1: a difference of 2.687 index points described as "within a point and a half", which editorial review caught, and the per-seller counts behind a comparable-series total, which were verified by hand against `numbers.json` before publication. Counts and worded quantities in prose rest on the editor, not on the gate.
- Corroboration (ACQUISITION §corroboration): no Internet Archive capture is triggered at fetch time. Planned.

- Chicken Monitor's wholesale weighted averages: report 3649 states the current and previous month only, so the year-over-year comparison for that series accumulates in this record rather than existing at the baseline, and no reading earlier than 2026-08 is held. The same holds for the CME reprints in Cheddar Check and the Egg & Butter Brief, which carry one week per report, and for the shell egg prices in report 2848 and the weekly broiler slaughter report, which carry the current and prior week. Until 2026-10-18 that accumulation was unreachable: `issue.py` built its series map from the named run alone, so each of these sources presented one period and no comparison of any kind could be computed, however long the record ran. The Cheddar Check CME series reported `weeks_in_record` as 1 while the record held five. Those sources are now declared `accumulates` and the comparisons the record has accumulated are available; the baselines have not been recomputed.

## Credentials

The BLS request carries a free registration key for the public API v2. v1 is keyless but allows 25 queries per IP per day, which six titles do not fit inside; v2 allows 500 and takes a title's whole series set in one request. The key is read from the environment at fetch time, is stored outside this repository, and appears in no capture file, data file, commit or built page. `<title>/sources.json` names the environment variable, which is what makes the recipe reproducible without publishing the credential: anyone with their own free key can run the same fetch.

## Naming

The cheddar title was named Cheddar Monitor when it was scaffolded on 2026-09-23 and renamed Cheddar Check the same day, before any edition published. Its directory, `cheddar/`, is unchanged, so no capture path, data file or anchored hash is affected. Chain entry 2026-09-23T153756Z and the commits before the rename carry the former name; they are history and are not rewritten.

## Local extensions

- Weekly series use `YYYY-MM-DD` week-ending periods; monthly series `YYYY-MM`; USDA ERS forecast attributes carry no period.
- Year-over-year for weekly series is the week ending nearest to 52 weeks earlier, within four days; stated in each data dictionary. The same nearest-week rule, within four days, pairs two weekly series that measure the same market on different week-ending days. Cheddar Check's mandatory-reported block less CME block weekly average is the case: the mandatory report's week ends Saturday and the CME reprint's week ends the Friday before, so no week is ever exactly shared and requiring an exact match left the measure uncomputable for every issue before 2026-10-18. The figure now records both week-endings and the offset in days.
- The wedding observation record at the path in `config.json` is read-only from here and is not part of this repository's anchor chain; its commit and file hash are recorded in each Lobster Monitor edition's `evidence.json`.
- The Dairy Market News running header names the report week, and a week that straddles a month end prints the second month: the issue for the week ending 2026-10-02 printed `DAIRY MARKET NEWS, SEPTEMBER 28 – OCTOBER 2, 2026` where the week ending 2026-09-25 printed `SEPTEMBER 21 – 25, 2026`. The header pattern read a single month and failed both DMN parsers on 2026-10-02, recorded as PARSE_FAILED for `ams_dmn_weekly` in `egg-butter/data/flags.jsonl` and `ams_dmn_cheese` in `cheddar/data/flags.jsonl`. Those flags stand. The pattern now takes an optional second month name and the week-ending month is read from it where it appears, so a week straddling a year end resolves as well; the readings were recovered by re-parsing the retained captures. The price patterns themselves matched throughout, so only the week-ending date was at issue.
- USDA NASS serves Quarterly Hogs and Pigs from `Todays_Reports` only for a window after each release, and the TRY chain is written to fall back across the quarterly cycle and take the most recent report available. On 2026-10-02 all four candidates returned 404 and the source was recorded FAILED. Two things follow, and the second is a correction. From 2026-10-02 the source also fetches the ESMIS archive page named in its `page_url` and follows the link for the release month it wants, so the quarterly reading no longer depends on the rolling directory; the NASS candidates are kept and tried first, and a row records which copy it was read from in `evidence_fetch`. The correction: the runs of 2026-09-23 and 2026-09-25 both resolved to `hgpg0626.txt`, the June release, not the September one. The September 2026 report was released September 24, 2026 and was never captured by those runs; the record carried the June release as the newest quarterly reading until 2026-10-02, when run 2026-10-02T225245Z read the September release from the archive and added the 2025-09 and 2026-09 periods. No reading was superseded or changed; a reading that was missing is now present.
- From 2026-10-25 the order is reversed. Because the NASS candidates were tried first and had aged out, every run from 2026-10-02 recorded the source PARTIAL although the archive copy was read without fault, and a permanent PARTIAL stops meaning anything. The archive is now fetched first and the NASS candidates only when it fails: a fetch may name another as `fallback_for`, and when that fetch succeeds the fallback is recorded SKIPPED with the reason and does not count against the source. A run that reads the archive is OK; PARTIAL now means the archive failed and the NASS copy was read; FAILED means neither arrived. Rows parsed from the archive already named `archive_txt` in `evidence_fetch`, so no reading changes. Tested on a scratch copy before the first live run: the archive path gave the same 42 rows as run 2026-10-23T220814Z.

- USDA AMS report 3649's reporting block is whole weeks and can start in one month and end in the next. The block ending 10/2/2026 began 8/31/2026 and is the September reporting month; its predecessor, 8/3/2026 to 8/28/2026, is August. `p_ams_chicken_pdf` took the month from the block's end date, so from 2026-10-02 the September block was recorded as 2026-10 and the record held no 2026-09 reading for this source while appearing to hold a complete October before any October block had been published. This is the same defect class as the Dairy Market News header below. The month is now the one holding most of the block's days, which resolves a block straddling a year end as well, and each row records `period_start` and `period_end` so the label is auditable. The retained captures of runs 2026-10-02T221955Z, 2026-10-09T221622Z, 2026-10-16T221612Z and 2026-10-18T145048Z were re-parsed and the readings are present under 2026-09. Nothing under `data/` was edited: the 2026-10 rows stand and each carries a `SUPERSEDED` entry in `chicken/data/flags.jsonl` naming the period it replaced, which is how `issue.py` skips a superseded reading.

- Figures whose exact decimal fell on a half printed one unit low until 2026-10-18. `fm()` formatted a float, and the nearest double to a value like 71.815 or 8.995 is just below it, so Python's own rounding gave 71.81 and 8.99 where the decimal rounds to 71.82 and 9.00. Both the formatter in `tools/issue.py` and the figure check in `tools/check.py` now round through `common.round_half_up`, which rounds half away from zero on the decimal the value prints as; they must share one rule, or a figure an edition prints would not match the figure the gate looks for. Every unpublished issue was regenerated. Two published editions were examined: Lobster Monitor Issue 0 is unaffected, and Issue 1 carries the prior-year lobster import unit value as $8.99 where the stored 8.995 rounds to $9.00. The percentage change beside it, +0.3%, is computed from unrounded values and is unaffected. That is a correction to a published edition and is recorded as one under §8.6 rather than silently rewritten. The defect was found by editorial review of the Egg & Butter Brief's four-week egg average, not by the gate, which was rounding the same way as the formatter and so agreed with it.

- An edition's evidence manifest must cover the captures behind accumulated readings. Declaring a source `accumulates` on 2026-10-18 moved the computed set across runs, but `evidence.json` was still built from the issue's own run alone, so an edition could rest on a four-week average whose earlier weeks appeared in no manifest. Found by editorial review of the Egg & Butter Brief, whose first issue rests on captures from five earlier runs. `tools/issue.py` now lists, for every source declared `accumulates`, the captures of each earlier run the computed set can reach, and every entry names its run and whether it is the issue's own run or accumulated history. An edition's claim that every capture behind it is listed is true again.

- Accumulated history reaches back, never forward. As written on 2026-10-18, `series_map` and the evidence manifest merged every other run of an `accumulates` source, later runs included, so recomputing an issue after the next weekly capture pulled weeks its own run had not seen: recomputing cheddar 2026-10 (run 2026-10-18T145249Z) on 2026-10-25 moved the CME barrel weekly average from 1.5095 to 1.704, the week ending 2026-10-23. Corrected 2026-10-25 to merge only runs earlier than the issue's run; run ids are UTC timestamps and sort in time order. No published figure was affected: every edition's numbers were computed before any later run existed, and after the correction all five 2026-10 computed sets recompute to the stored values unchanged apart from `computed_at`.

- The CME reprint in Dairy Market News does not space its figures consistently between issues. The issue for the week ending 2026-09-25 printed the butter weekly average as `AA is $ 1.3645`, with a space after the dollar sign; the week ending 2026-09-18 printed `$1.3590`. Both DMN parsers now tolerate whitespace there. The 2026-09-25 run recorded PARSE_FAILED for `ams_dmn_weekly` before the parser was widened; that flag stands in `egg-butter/data/flags.jsonl` and the reading was recovered by re-parsing the retained capture, which is what supersession means here.
